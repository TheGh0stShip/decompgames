## GTA SA Reversed

The old `gta-reversed/gta-reversed-modern` URL redirects to canonical `gta-reversed/gta-reversed`, pinned at `04c5b6643a9059e879f6015ec02e618f141fb27a` (1,048 stars at read). This is one implementation of one game. The [README](https://github.com/gta-reversed/gta-reversed/blob/04c5b6643a9059e879f6015ec02e618f141fb27a/README.md) describes reversed functions replacing functions inside the running original game, through an ASI-loaded DLL. It estimates roughly 50–60% completion; that is an upstream estimate, not a reproduced metric. It requires the specific Compact executable of 5,189,632 bytes. None of that executable, the loader, plugin releases or original game data was downloaded.

GitHub reports no license, and the untruncated pinned tree has no file with a license/copying/notice basename. This does not prove that every individual source lacks a grant; it means a grant covering the intended reconstructed game distribution was not established. Replacement assets would not resolve that code gate.

The [Conan recipe](https://github.com/gta-reversed/gta-reversed/blob/04c5b6643a9059e879f6015ec02e618f141fb27a/conanfile.py) permits only `standalone=False` and `dump_hooks_only`, explicitly saying that a fully standalone game cannot yet be built. Hook dumping is not gameplay. [CMake](https://github.com/gta-reversed/gta-reversed/blob/04c5b6643a9059e879f6015ec02e618f141fb27a/CMakeLists.txt) uses C++23 and CMake 4.2; the documented route is Windows tooling. Conan selects SDL 3.4.14 optionally, nlohmann_json 3.12.0, spdlog 1.17.0, Tracy cci.20220130, ImGui 1.92.9b-docking, header-only Boost 1.91.0, Ogg 1.3.5, Vorbis 1.3.7 and libjpeg-turbo 3.2.0. Its ImGui bindings still select DirectX 9. Those are dependency selections, not a verified license/runtime closure, and SDL alone does not make the game portable.

Reopen after a suitable whole-code provenance/grant route, a complete independent runtime, a browser platform adaptation and independently authored graphics, animation, text, maps and audio contracts exist. A retail executable running with replaced hooks would not satisfy this intake.

## KAIN2 / Legacy of Kain: Soul Reaver

`Gh0stBlade/KAIN2` is pinned at `e9fa662a02ab597af1e2b2b8e4d1a6af02c180ef` (175 stars at read). The [README](https://github.com/Gh0stBlade/KAIN2/blob/e9fa662a02ab597af1e2b2b8e4d1a6af02c180ef/README.MD) describes MIPS-to-C decompilation and a native port. Its 78% progress badge is not independently verified. [Contribution rules](https://github.com/Gh0stBlade/KAIN2/blob/e9fa662a02ab597af1e2b2b8e4d1a6af02c180ef/CONTRIBUTING.MD) require code matching the July 14, 1999 review build, including proof for automatically decompiled contributions. These support the decompilation classification, not a clean-room claim or a complete reproduced binary.

**The Unlicense label is not a verified grant.** Repository metadata reports `Unlicense`, but the complete pinned tree contains no license/copying/notice file, and the repository license endpoint returned HTTP 404 during this review. The inspected README, contribution guide and build files do not supply the missing distribution grant. Establish the actual grant and its inherited-code scope before compiling for release; metadata alone cannot clear reconstructed original logic.

The native CMake target links pinned `Gh0stBlade/libValkyrie` at `d9c65047db93698b1c32b4d84cb4318c566f3a50`. That dependency's complete tree also has no license/copying/notice file. Three sampled interface/GPU/GTE source files contain no permission notice. This is a bounded inspection, not a claim about every file or its origin. `GPL` strings in the sampled GTE source name a graphics instruction and are not a GPL license declaration. The inspected targets compile reconstructed game C and a platform library; the library's “Emulator” name alone does not establish whole-game CPU emulation. Platform emulation/compatibility and inherited library provenance still need review.

SDL's native gitlink is `031912c4b6c5db80b443f04aa56fec3e4e645153`; its [zlib-style notice](https://github.com/libsdl-org/SDL/blob/031912c4b6c5db80b443f04aa56fec3e4e645153/LICENSE.txt) was inspected separately. The emsdk gitlink `e2627e265d940db5ea58dffa63e490375bfc92e5` has an [MIT notice](https://github.com/emscripten-core/emsdk/blob/e2627e265d940db5ea58dffa63e490375bfc92e5/LICENSE). Neither clears libValkyrie, inherited game code, the downloaded compiler/runtime or all SDL components. The Web route uses the SDK's `USE_SDL=2` port instead of the native SDL submodule; no resolved browser dependency closure exists here.

There is specific browser potential: [game Emscripten flags](https://github.com/Gh0stBlade/KAIN2/blob/e9fa662a02ab597af1e2b2b8e4d1a6af02c180ef/KAIN2/Game/Platform/Emscripten.cmake) select WASM, WebGL2, SDL2, Asyncify and pthreads, and the README links a WebGL demo. However, the contribution guide crosses out Web build instructions. The game links a specific `Build/Build_EMSDK/External/libValkyrie/libValkyrie.a` path; the library's `Valkyrie` output name is consistent with the normal static-library prefix. Build output alignment, thread isolation, scheduling, file preloading and SDK compatibility remain untested. The upstream demo was not opened and supplies no ROM-free or gameplay verification.

The contribution guide requires original `BIGFILE.DAT` and `LOCALS.TBL`; debug mode extracts the original archive, and release mode reads it directly. [LOAD3D](https://github.com/Gh0stBlade/KAIN2/blob/e9fa662a02ab597af1e2b2b8e4d1a6af02c180ef/KAIN2/Game/LOAD3D.C) also retains archive-directory/file reads in `PSXPC_VERSION`/`NO_CD` paths. Disabling CD access does not remove original content requirements. Neither named data file is present in the pinned tree. No independent graphics/models/animation/audio/text/streaming-world pack was established. Reopen after actual code/library grants and provenance are documented, all expressive content is independently replaced with a manifest, and the native game completes a scoped ROM-free muted browser acceptance test.

The [README](https://github.com/lethal-guitar/BioMenaceDecomp/blob/4471bcfc03ff2ebe10620011fa45e9a1d086c841/README.md) reports exact episode-one freeware and shareware binary reconstruction, using Commander Keen reconstruction as its engine basis. [MAKEFILE](https://github.com/lethal-guitar/BioMenaceDecomp/blob/4471bcfc03ff2ebe10620011fa45e9a1d086c841/SRC/MAKEFILE) selects BCC/TLINK/TASM, Borland startup/library inputs and `DATA/BM1INTRO.OBJ`. No object or tool binary was fetched, and no grant was inferred for those separate inputs. Original game data remains required and is not included. DOS emulation would not become a native decomp port by relabeling it. Reopen only if the accepted code-license route changes or a suitable alternative grant exists, followed by inherited-code/runtime review, a portable build and a full independently authored content pack.

## OpenMBU

`MBU-Team/OpenMBU`, `3d6516e1c9cb43e61aead3369d1f7210d08b83ef` (258 stars), uses an [OpenMBU Fan Revival License](https://github.com/MBU-Team/OpenMBU/blob/3d6516e1c9cb43e61aead3369d1f7210d08b83ef/LICENSE.md). It allows only noncommercial remixing/sharing and excludes rights to original IP. That is not the currently accepted permissive route. The separate OpenMBU+ edition has different terms and was not audited or counted as another game. The README calls this a revival and the license calls it a recreation; matching reconstruction evidence was not established.

Selected dependency notices were inspected separately: Assimp/BSD-3-Clause (with explicit test-model exceptions), curl's permissive notice, Discord RPC/MIT, RapidJSON/MIT plus its BSD component and JSON-checker exception, and an Ogg/Vorbis BSD-style notice. [Native targets](https://github.com/MBU-Team/OpenMBU/blob/3d6516e1c9cb43e61aead3369d1f7210d08b83ef/tools/cmake/marbleblast.cmake) select Assimp, curl, Discord RPC, RapidJSON and additional libraries; the checked Vorbis notice is in a different vendored directory from the `libvorbis` target. It therefore is not proof of the selected target's entire licensing. The RapidJSON checker restriction is not assumed to enter the game. No exact linked closure or complete third-party clearance is claimed.

The build has native Windows DirectX 9 and desktop Unix/macOS paths, including x86-oriented flags/NASM; no working browser target was established in the selected files. The tree has game assets and old-project content without a verified independently authored CC0 pack. Dependency notices or an MIT Torque engine fork would not supersede the main project's custom terms or clear its original content. Reopen only after an acceptable code grant/provenance route, independent content and a verified browser adaptation exist, and recreation work is authorized again.
