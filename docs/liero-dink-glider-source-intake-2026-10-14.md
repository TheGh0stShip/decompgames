## OpenLiero: permitted data with explicit sound exceptions

The current [BSD-2-Clause source notice](https://github.com/openliero/openliero/blob/86f2fae43380447db9a5b1ceb181cbe5e25b3f61/LICENSE) credits the OpenLiero contributors. The [official history](https://www.liero.be/) describes OpenLiero as a faithful clone and successor. That does not establish byte-exact matching or a certified clean-room process. Reverse engineering alone does not distinguish a matching reconstruction from a recreated engine; this intake conservatively retains the latter classification.

The official site's current [1.35-era notice](https://www.liero.be/licenses/135/license.txt) grants WTFPL to original Joosa Riekkinen data and binary files unless otherwise stated. It separately identifies SMIX's BSD-3-Clause declaration and Molez-derived sounds under freeware distribution terms. It explicitly says the old LIEROENG.TXT terms no longer apply. The linked [1.33 document](https://www.liero.be/licenses/133/license.txt) still contains historical unchanged-package freeware wording; that older document must not be the sole current permission basis. Its non-UTF-8 encoding caused a web-reader decoding error, but the exact bytes were fetched and read privately; it is not a missing licence endpoint. The first guessed root `/license.txt` URL returned 404 and was replaced by the actual linked paths.

The separate [lierolibre notice](https://www.liero.be/licenses/libre/license.txt) explicitly identifies original graphics, replacement sounds and extracted configuration variables under WTFPL. Current OpenLiero's [sound notice](https://github.com/openliero/openliero/blob/86f2fae43380447db9a5b1ceb181cbe5e25b3f61/data/TC/openliero/sounds/LICENSE) names the replacement author “sea” and the covered WAV files. Thus this lead has specific data permission evidence, beyond a root code badge. Original LIERO.SND is not cleared by calling it freeware and should remain excluded. Original binary/SMIX bytes need not be shipped in the modern source build.

This screen did not establish a per-file origin/hash mapping between the older permitted resource set and every present TGA, configuration, level and application icon. That mapping, modern added-content grants and independently authored replacements for any gaps remain distribution gates. No sprite/audio/level binary was downloaded. The historical lierolibre package notice also makes an unusual claim about proprietary MSVC runtime licensing; it is not accepted as authority to relicense Microsoft's runtime. Its old SDL1/libconfig LGPL shared libraries are not automatically dependencies of the current SDL3 WASM selection.

The current [CMake Web branch](https://github.com/openliero/openliero/blob/86f2fae43380447db9a5b1ceb181cbe5e25b3f61/CMakeLists.txt) preloads Profiles, Resources, Setups and TC into `/openliero`, not a ROM or DOS executable. [gfx.cpp](https://github.com/openliero/openliero/blob/86f2fae43380447db9a5b1ceb181cbe5e25b3f61/src/game/gfx.cpp) actually uses `emscripten_set_main_loop_arg` and cancellation; browser feasibility is stronger than an SDL library merely mentioning Emscripten. Native return-path cleanup is not proven to execute after the simulated infinite browser loop. Sound-player construction opens and resumes an SDL audio stream unless `DISABLE_SOUND` applies: a future silent edition must explicitly enforce mute before testing.

Dependency closure remains open. The actual target lists SDL3/image, miniz, ENet, libjuice, toml++, xxHash and cereal, with Catch2 in the package manifest and optional Tracy/video tooling. The [vcpkg registry](https://github.com/openliero/openliero/blob/86f2fae43380447db9a5b1ceb181cbe5e25b3f61/vcpkg-configuration.json) pins baseline `031f4afe03be385aee354f15be6e6b1fe57497c7`; overlay recipes carry archive SHA-512 checks, not yet-resolved library grants or linked closure. The bootstrap script has its own BSL-1.0 SPDX notice. The older README's GPL-enabled FFmpeg/x264 instructions concern an optional video tool, not proof that the current Web game links GPL codecs. No dependency installer/bootstrap was executed.

Conditional reopening work: confirm the intended non-decompilation port scope against the current decompilation-first priority; inventory the exact stock resources and replace uncovered additions; pin/audit the selected dependency and SDK notices; build the silent edition; verify ordinary combat, damage, win/restart, controls, persistence and full stop/unload. This candidate was preserved rather than rejected for lack of all original-data permission.

## Dink: developer permission is real; the selected Web library is separate

The developer's [current custom licence](https://github.com/SethRobinson/RTDink/blob/4ac274bea96247897316a3b61abfa480f939444b/LICENSE.md) permits source reuse with retained notices, legible in-app attribution and name/promotion conditions. It is not plain MIT. It describes original game data's 2008 zlib-style release and grants HD media created by the developer, while explicitly warning that some sounds have unknown/library origins. Its authorization for the complete official HD application must not be extended to a separately published DecompGames package. The exact permissible media subset or full independently authored replacements still need a manifest.

The selected [HTML5 build script](https://github.com/SethRobinson/RTDink/blob/4ac274bea96247897316a3b61abfa480f939444b/html5/build_release.bat), not just native build instructions, links `fmodstudioL_wasm.a` from the external Proton SDK tree. That archive has no verified permissive grant in this screen. The script also preloads `bin/interface`, `bin/audio` and `bin/dink_html5`, uses Asyncify, IDBFS and legacy SDL settings. The pinned repository has no Proton tree/gitlink and no `bin/dink_html5` tree: those external/staged inputs must be reproducibly supplied. Desktop SDL2_mixer support does not establish that the Web target excludes FMOD. No library/SDK binary or official ready-made game bundle was downloaded.

Two SoundFont notices were read independently from game licensing: TimGM6mb declares GPL-2.0; GeneralUser GS gives broad complete-work permission but expressly acknowledges uncertain origins of some samples. Neither is CC0, and neither notice is extended to other music/sounds. Their file presence alone does not prove the exact Web pack includes them; selected payload inventory remains required. No SoundFont bytes were fetched.

Reopening gates: confirm acceptance of the custom source conditions for the selected release; replace or separately authorize the actual Web audio library; pin Proton and its transitive code/media grants; resolve missing staged content and inventory/rewrite unclear media; then build and test ROM-free gameplay, saves and teardown with enforced mute. This remains a source-port lead and cannot satisfy the matching-decompilation milestone.

## Glider 4: original source and contributed houses differ

The [original author's MIT notice](https://github.com/softdorothy/Glider4/blob/d023891da740a41d192e25d0e748fd1c54d940b8/LICENSE) accompanies released Pascal code. The [browser fork](https://github.com/kodogo/Glider/blob/9d5ff29905531e2d3c238a4c988f29d4f4ab1802/README.md) describes a close JavaScript translation, changed timing and some remaining reference/global-variable bugs; it retains the original MIT notice. This supports a developer-source port classification. It is separate from Glider PRO's GPL release and from similarly named JavaScript carousel/UI projects.

The original tree includes legacy binary objects/libraries and Macintosh resource files. The selected Pascal SMS interface declares external procedures; this is not source or permission closure for its linked binary implementation. Those binary inputs were not fetched and do not establish the browser fork's dependencies. The browser [index](https://github.com/kodogo/Glider/blob/9d5ff29905531e2d3c238a4c988f29d4f4ab1802/glider/index.html) loads twelve local scripts; its inspected QuickDraw compatibility file uses Canvas primitives. These observations are not full JavaScript/dependency or gameplay acceptance.

At least one original house README explicitly credits a separate contributor, Brian Eaton, rather than the root licence holder. No separate contributor grant was established by that text. No contributor address/contact details are reproduced here. House files, converted PNGs, fonts and audio need individual origin/licence evidence or independently authored replacements; root MIT does not certify them all. The browser's `g-houses.js` is 1,123,559 bytes and exceeded the one-million-byte selected-text bound, so it was not fetched/reviewed. This open script/content boundary is recorded rather than silently treated as cleared.

Reopening gates: audit all actual scripts and embedded expressive content, establish current translation/contributor grants, create independent houses/art/font/audio/text for uncovered inputs, enforce silent startup, and verify normal flight/collisions/objectives/lives/restart/persistence/Stop. A browser game that loads is not a complete gameplay test; neither translation nor author-released code is a matching decompilation.
