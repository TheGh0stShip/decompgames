## Azel / Panzer Dragoon Saga

`yaz0r/Azel`, revision `c52329fb257561abff05531a8335e34137d67098`, 173 stars at read. Classification: incomplete decompilation/reverse-engineering-derived native game port with hardware compatibility and sound-system emulation. The [README](https://github.com/yaz0r/Azel/blob/c52329fb257561abff05531a8335e34137d67098/README.md) supports Windows/VS2022, requires CD1 content in the data directory and reports a buggy early segment through the Arachnoth battle. This is upstream's status, not our gameplay verification. No complete independent replacement content pack or original rights-holder grant for reconstructed game code was established. The [MIT declaration](https://github.com/yaz0r/Azel/blob/c52329fb257561abff05531a8335e34137d67098/LICENSE), copyright 2024 Azel authors, is separate from those gates.

A concrete dependency restriction exists in the selected source list: [AzelLib CMake](https://github.com/yaz0r/Azel/blob/c52329fb257561abff05531a8335e34137d67098/AzelLib/CMakeLists.txt) compiles AOSDK's M68K CPU, SCSP and DSP files. The actual [m68kcpu.c header](https://github.com/yaz0r/Azel/blob/c52329fb257561abff05531a8335e34137d67098/ThirdParty/aosdk/eng_ssf/m68kcpu.c) identifies Musashi 3.3 with noncommercial permission and other terms requiring author negotiation. The bundled [per-file licence inventory](https://github.com/yaz0r/Azel/blob/c52329fb257561abff05531a8335e34137d67098/ThirdParty/aosdk/license.txt) assigns SCSP/DSP/LFO to older MAME terms prohibiting sale/commercial use. It also lists GPL components elsewhere; that does not prove those other components are linked here. The root MIT licence does not replace these selected restrictions. Muting playback alone would not remove compiled restricted code or original sound-program data.

[PDS CMake](https://github.com/yaz0r/Azel/blob/c52329fb257561abff05531a8335e34137d67098/PDS/CMakeLists.txt) has an Emscripten branch using GLESv2/WebGL2 and preloading `data`, with older memory/export flags. It also links SDL3, SoLoud and bgfx. This is documented browser potential despite the README's supported Windows path, not a verified current browser build. All remaining dependencies, actual linked closure, scheduler/storage and generated shader inputs need a release audit. Reopening requires permissive alternatives or grants for restricted audio components, reconstructed-code provenance, full independent graphics/models/animation/maps/text/audio/video, runtime completion and current ROM/disc-free browser gameplay/save/rebuild evidence.

## Super Mario 64 DS matching decompilation and native source port

`tangosdev/sm64ds-decomp`, revision `731efc06d5d5e84ac33ff5f97880e9f90476158e`, 191 stars at read. The [root README](https://github.com/tangosdev/sm64ds-decomp/blob/731efc06d5d5e84ac33ff5f97880e9f90476158e/README.md) describes byte-matching C/C++ reconstruction and a native Windows port using a supplied cartridge dump. Its licence section confines MIT to project original work and grants no Nintendo-material rights; [LICENSE](https://github.com/tangosdev/sm64ds-decomp/blob/731efc06d5d5e84ac33ff5f97880e9f90476158e/LICENSE) names Tango, copyright 2026. This declaration and the author's from-scratch description do not independently certify clean-room isolation or resolve reconstructed retail/SDK source permission for this intake.

The pinned [port README](https://github.com/tangosdev/sm64ds-decomp/blob/731efc06d5d5e84ac33ff5f97880e9f90476158e/port/README.md) still describes a 32-bit Windows smoke-executable suite, while the root README advertises a native game download. Do not turn that older port document into a conclusion that all current upstream releases are unplayable. No downloaded release or browser target was tested here. The reviewed [port CMake](https://github.com/tangosdev/sm64ds-decomp/blob/731efc06d5d5e84ac33ff5f97880e9f90476158e/port/CMakeLists.txt) builds smoke targets and generates constants from `extracted/arm9_dec.bin`. [romdata.py](https://github.com/tangosdev/sm64ds-decomp/blob/731efc06d5d5e84ac33ff5f97880e9f90476158e/port/tools/romdata.py) confirms that source, and [the filesystem seam](https://github.com/tangosdev/sm64ds-decomp/blob/731efc06d5d5e84ac33ff5f97880e9f90476158e/port/hal/fs.cpp) reads a ROM-generated catalog and extracted game files. Replacing only external images would leave generated data requiring separate provenance. The hardware-layer README describes memory mapping, fibers and software DS graphics compatibility; native game code should not be conflated with whole-game CPU emulation or a browser-ready implementation.

Blockers: reconstructed code/SDK grant scope, complete independent content and generated-data replacements, selected dependency closure, a portable build and muted ROM-free browser gameplay/save/rebuild verification. No independent full pack or verified WebAssembly target established.

## Separate SM64DS static recompilation

`mstan/supermario64dsrecomp`, revision `deb9973373d052ae7ca0d72f7849b6076f21ad81`, 8 stars at read. This is a related alternative, not another game title. The [README](https://github.com/mstan/supermario64dsrecomp/blob/deb9973373d052ae7ca0d72f7849b6076f21ad81/README.md) says it uses decompilation metadata rather than compiling the matched C, then statically translates ARM9/ARM7 banks from a supplied ROM. Classification: static recompilation with DS device models and fallback paths, not source decompilation. A ROM-free download is not ROM-free gameplay. Its scaffold MIT grant is separate from the documented GPL-3.0-or-later combined runner and translated game-code provenance. No permissive whole-distribution or browser gameplay clearance established.

README now documents FreeBIOS fallback while the packaged BIOS note still requires dumps: record the discrepancy, do not claim all launch paths need retail BIOS. The required game ROM, generated-bank rights, independent full content, selected runtime terms and unverified Web build remain sufficient blockers regardless of BIOS choice.

No eligible release from this audit. Mario Party 2/3 and Halo are untouched. Private ROM research and full read-only source snapshots remain private; no clean-room certification, broader gameplay claim or deployment.
