Six title candidates, three project lineages, five current/legacy repository pins and one historical licence pin were screened. None is ready for DecompGames distribution under the current permissive-code and independently authored content requirements. The catalog remains 86; the matching-decompilation milestone remains 4/5. No build, player, deployment or gameplay test was performed in this pass.

The companion source snapshot records selected textual evidence URLs, byte counts and SHA-256 hashes. Complete tree metadata was inspected privately to choose files; this is not a full source or dependency audit. Original retail archives, executables, disc images, SDK/library binaries and external artwork were not acquired. Source-contained expressive text was inspected privately and is not copied into these documents. Prior private ROM research is excluded. Mario Party 2/3 and Halo were untouched.

## OpenGOAL: native backends are not WebAssembly backends

The [root licence](https://github.com/open-goal/jak-project/blob/b6c8430c0b0a5cb139b939bcf0ffd25285b896c7/LICENSE) grants ISC for OpenGOAL Team work. The [README](https://github.com/open-goal/jak-project/blob/b6c8430c0b0a5cb139b939bcf0ffd25285b896c7/README.md) documents recovery of original GOAL through decompilation and annotation, and requires a legitimate game copy for resources. No separate original rights-holder grant for recovered retail code or a complete independently authored replacement resource pack was established by this selected-file screen. This is an unresolved distribution boundary, not a finding that every source file lacks a licence.

The actual [code generator](https://github.com/open-goal/jak-project/blob/b6c8430c0b0a5cb139b939bcf0ffd25285b896c7/goalc/compiler/CodeGenerator.cpp) selects X86 or ARM64 and rejects unsupported instruction sets. The [runtime build](https://github.com/open-goal/jak-project/blob/b6c8430c0b0a5cb139b939bcf0ffd25285b896c7/game/CMakeLists.txt) selects native x86-64 NASM or ARM64 assembly. Kernel `codegen.h` writes executable machine-code stubs. Thus the current source supports ARM64 in addition to the x86-64 route described prominently in the README. This screen does not establish ARM64 gameplay acceptance.

Compiling the C++ tools with Emscripten would not make their emitted native GOAL instructions execute in WASM. A browser route needs a WASM-compatible compiler/runtime calling boundary, replacements for executable-memory stubs and native assembly, and adaptations for graphics, scheduling, filesystem, audio and shutdown. No project-owned browser recipe was found in the inspected tree; third-party SDL web support is not game-port acceptance. No claim of impossibility is made.

Selected dependency grants were read separately: vendored SDL is zlib, cubeb and libco are ISC, Discord RPC and fmt are MIT (fmt includes its object-code notice exception). The inspected xdelta3 directory carries Apache-2.0; it must not be labelled GPL from a different version. `vendor.yaml` identifies SDL 3.4.10 and other upstream references, but those annotations do not prove all vendored files equal those releases. Runtime links also include common, graphics/glad, imgui, sound, stb_image, libcurl and platform libraries; compiler/decompiler tools have further dependencies. Per-file grants, transitive libraries and final build selection remain unaudited. There are no gitlinks at this repository pin.

Reopening conditions: resolve the recovered-code distribution scope; define and author a complete independent resource contract; implement and verify a browser code-generation/runtime route; close the selected dependency notices; then perform silent ROM-free gameplay and lifecycle tests. A generic new game using a newly authored engine would be an original replacement, not a Jak matching decompilation release.

## R.E.L.I.V.E.: current grant and compiled GPL component

The current [README](https://github.com/AliveTeam/alive_reversing/blob/3be8967b71b29e6e61009d291bd64dce39abf7ac/README.md) says contributed code will receive a GPL-compatible licence in the future, probably MIT/Expat. No current root LICENSE/COPYING was present in the inspected tree. The [legacy MIT grant](https://github.com/MrSapps/alive/blob/9c3a45d618a4f7a33a6f3da3987e2c1947d1588b/LICENSE), copyright 2015 paulsapps, is evidence for that legacy repository; it cannot by itself license all later AliveTeam contributions.

There is also a concrete selected-source incompatibility with the current permissive-only intake: [PSXMDECDecoder.cpp](https://github.com/AliveTeam/alive_reversing/blob/3be8967b71b29e6e61009d291bd64dce39abf7ac/Source/AliveLibCommon/PSXMDECDecoder.cpp) carries GPL-2.0-or-later, credits its prior authors and derives from libbs. [AliveLibCommon/CMakeLists.txt](https://github.com/AliveTeam/alive_reversing/blob/3be8967b71b29e6e61009d291bd64dce39abf7ac/Source/AliveLibCommon/CMakeLists.txt) compiles this decoder into the common game library. A proposed MIT root notice would not remove that separate obligation. A future permissive route would need an authorized alternative implementation or an applicable separate grant, as well as a current whole-project grant. No such change was attempted.

The standalone [entry point](https://github.com/AliveTeam/alive_reversing/blob/3be8967b71b29e6e61009d291bd64dce39abf7ac/Source/relive/Exe.cpp) returns false from `RunningAsInjectedDll` and calls the reconstructed AO/AE functions. It requires `s1.lvl`/`r1.lvl` for Oddysee or `st.lvl`/`mi.lvl` for Exoddus before starting. Resource loaders and original-address mapping macros were inspected. These support reverse-engineered native reconstruction; they do not prove byte-exact matching, clean-room isolation or whole-machine emulation. The video/audio format decoders are not evidence that the entire game uses CPU emulation.

Current build selection uses C++17 and system SDL3, despite an old README output example naming SDL2.dll. The common library links EasyLogging++, googletest and Cinder as well as SDL3; googletest is not automatically excluded as test-only here. Detours is conditionally compiled on 32-bit Windows; injected DLL targets are platform-conditional. Exact submodule pins are recorded in the snapshot, but their grants and the vendored older DirectX headers were not closed. No browser recipe or full independent level/animation/art/text/audio pack was verified.

Reopening conditions: establish current contributions' grant, replace or separately authorize the compiled GPL decoder for a permissive route, audit selected dependencies and embedded data, supply complete independent resources, and implement/test a browser host. Broad engine-recreation expansion remains paused; this classification screen did not start a recreation prototype.

## TH08: a real web port still needs content and code closure

Both current [native](https://github.com/N0zoM1z0/th08/blob/4fe9ce6124f1e6008ef24592fe1ac2c4a2aeb3c4/LICENSE) and [web](https://github.com/N0zoM1z0/th08-web/blob/e3485ab9a9af3b5a90ce51841667bbdf5a867e5c/LICENSE) notices are MIT, preserving 2025 KSS and adding 2026 N0zoM1z0. The historical [imported snapshot notice](https://github.com/N0zoM1z0/th08/blob/7ad379297baf4ff07f117747ea4edf8c7ed739d4/LICENSE) was separately fetched and verified as MIT. The README documents imported history and continued analysis against a retail executable. Full ancestry was not locally replayed. Agent-produced reconstruction and retained contributor credit are not proof of clean-room isolation or an original rights-holder grant.

The [Web CMake branch](https://github.com/N0zoM1z0/th08-web/blob/e3485ab9a9af3b5a90ce51841667bbdf5a867e5c/CMakeLists.txt) compiles the shared C++ game/PBG archive sources and modern compatibility adapters to WASM; it returns before Windows SDK linking. The proprietary VC7/DirectX library entries in `config/library-provenance.toml` describe exact native reconstruction dependencies, not proof that those binaries enter the selected browser build. Detours' gitlink likewise does not establish its use in the Web target.

The [web recipe](https://github.com/N0zoM1z0/th08-web/blob/e3485ab9a9af3b5a90ce51841667bbdf5a867e5c/scripts/build-web-game.sh) pins Emscripten 6.0.8 by Docker digest. The selected link uses SDL2, SDL2_image PNG/JPEG and SDL2_ttf ports, pthreads, WebGL2, shared 256 MiB memory, a 4 MiB stack and IDBFS. Actual SDK port revisions, image/font dependency configuration and source/notice closure have not been resolved locally. No container was pulled or build executed. The current Web text path uses browser canvas/system sans-serif; it does not bundle MS Gothic merely because the original face name occurs in `i18n.csv`. No font-file bytes were fetched.

The [launcher contract](https://github.com/N0zoM1z0/th08-web/blob/e3485ab9a9af3b5a90ce51841667bbdf5a867e5c/README.md) requires `th08.dat` and `thbgm.dat`. Local file selection and excluding DATs from deployment do not satisfy the intake requirement for gameplay without original game files. No complete independent ANM/art/animation, ECL/stage, dialogue/text, ending, sound/music and resource archive set with provenance was verified. Source-side `config/i18n.csv` contains 195 rows including retail-title/character strings, and CMake generates compiled text from it; replacing external archives alone therefore would not audit every expressive-content boundary.

The [upstream provenance gate](https://github.com/N0zoM1z0/th08-web/blob/e3485ab9a9af3b5a90ce51841667bbdf5a867e5c/scripts/check-web-provenance.py) checks forbidden names/extensions, persistence declarations and a nine-file deployment allowlist. It explicitly is not a licence detector. It cannot prove code provenance, independently authored strings or the contents of WASM/icon bytes. The project-owned icon claim remains upstream documentation, not an independent pixel/provenance audit. Upstream long-route browser tests used retail data; no such tests were repeated here. A future DecompGames player must start muted and verify stop/unload as well as actual objectives, input and persistence.

Reopening conditions: establish the selected reconstructed code and headers' distribution scope, audit/rewrite embedded expressive content independently, author the complete resource set and manifest, close the exact SDK/port dependency notices, then build and test the resulting source-built game without retail inputs. TH08 remains the strongest browser-engineering lead in this group, with an unresolved distribution boundary.
