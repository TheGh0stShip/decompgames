## Animal Crossing GameCube

`flyngmt/ACGC-PC-Port`, revision `4099d246c927e75b4fd342ca13f4ac4395c55af5`, 1,485 stars at the API read. The [README](https://github.com/flyngmt/ACGC-PC-Port/blob/4099d246c927e75b4fd342ca13f4ac4395c55af5/README.md) identifies native original C on a custom GX-to-OpenGL layer. This is a decompilation-derived native port, rather than whole-game CPU emulation or an independently authored recreation. Its primary game is distinct from the existing Nintendo 64 catalog entries.

The [port notice](https://github.com/flyngmt/ACGC-PC-Port/blob/4099d246c927e75b4fd342ca13f4ac4395c55af5/LICENSE) separately declares the upstream reconstruction CC0 and the PC adaptations MIT, copyright 2026 FlyingMeta. The upstream `ACreTeam/ac-decomp` was independently pinned at `09ca8e8b5b24e6ab44047ee980cf0088ad7ecb4c`, 1,409 stars, and its CC0 declaration and matching-build instructions were read. That is not evidence of an original Nintendo grant covering all reconstructed game/SDK source or retail content. It does not certify clean-room isolation. The current upstream pin is a separate observation, not a verified ancestry pin for every file copied into the port.

The [PC CMake source selection](https://github.com/flyngmt/ACGC-PC-Port/blob/4099d246c927e75b4fd342ca13f4ac4395c55af5/pc/CMakeLists.txt) compiles reconstructed game sources, `jaudio_NES`, selected compatibility/runtime code and vendored FixNES. It excludes several original platform/compiler implementation files and substitutes host layers, but this is not a complete inherited-code provenance audit. FixNES has a separately reviewed MIT notice, copyright 2017 FIX94. Its presence means emulated NES subgames must be distinguished from the main native game. The generated GLAD source declares `(WTFPL OR CC0-1.0) AND Apache-2.0`, and the Khronos header retains its own MIT-style grant. Neither component is covered merely by the port's MIT notice. SDL2 may come from system or fallback paths; no exact final SDL2/compiler/runtime closure was built or reviewed.

[The DVD seam](https://github.com/flyngmt/ACGC-PC-Port/blob/4099d246c927e75b4fd342ca13f4ac4395c55af5/pc/src/pc_dvd.c) reads the disc image first and can fall back to extracted files. An extracted-file fallback does not establish independent content. The representative model source `src/data/model/obj_notice.c` contains material/display-list structures while the PC branch allocates texture/vertex buffers for runtime loading. Original content expressed in source-side tables and structures therefore needs separate classification; replacing external textures alone is insufficient. The large `pc_assets.c` text was not saved or reviewed after exceeding this screen's bound; its full content contract remains a precise open item.

The native target requires 32-bit pointer semantics for JSystem casts, creates an OpenGL 3.3 core context, links desktop SDL2/GL and uses native platform branches. Those observations identify porting work; they do not prove a browser port impossible. Reopening requires an acceptable inherited game/SDK grant/provenance route, complete independently authored expressive data with a manifest, exact selected dependency notices, a muted yielding WebAssembly/WebGL host, and representative gameplay/save/rebuild verification. No original disc is needed for the proposed independent-content route.

## Touhou 6: matching CC0 versus portable GPL

The setup was inspected as text and never run; none of those proprietary binaries was downloaded.

Its [LICENSE](https://github.com/GensokyoClub/th06/blob/9719f2f9c45b42de81e892289096135dc153699a/LICENSE) is GPL-3.0, and `Wavy667/th06-vita` at `41f4bec235fd0b6d2ad772862cb326f3a9634e26` has the same GPL notice. These do not meet the current permissive-code gate. The matching branch's CC0 declaration is neither a licence for the portable adaptations nor permission for original game content.

The [portable build list](https://github.com/GensokyoClub/th06/blob/9719f2f9c45b42de81e892289096135dc153699a/premake5.lua) uses C++20, SDL2, SDL2_image and SDL2_ttf, optionally system ALSA, generated shader text and a Shift-JIS converter. Versions and transitive codec/font grants are not fixed by this selected build review. Converter sources have no local attribution notice in the inspected files; their separate provenance remains unestablished, rather than assumed CC0. Munit's matching-branch gitlink is test tooling and was not certified as a linked runtime dependency.

The portable source includes `src/graphics/WebGL.cpp`, but [main.cpp](https://github.com/GensokyoClub/th06/blob/9719f2f9c45b42de81e892289096135dc153699a/src/main.cpp) retains a blocking event/render loop and initializes sound. No yielding Emscripten scheduler, browser save route or current WASM gameplay was verified. The Vita build's SDK/vitaGL target is another platform, not a browser acceptance result.

Both playable port descriptions require original DAT archives and music plus a compatible font. Copying Windows `msgothic.ttc` is not CC0 font provenance. Complete independent stages/scripts, textures/sprites, character animation, effects, text, font and audio remain absent. Reopen only with an accepted code route or separately authorised licence change, inherited-code/dependency provenance, a full independent content pack and muted browser gameplay/save verification. The current GPL exclusions require no build to establish.

## Resident Evil 1 PC

`ecruells/resident-evil-pc-decomp`, revision `15004914527567a2b9cecf34997abe8c252bcbf9`, 133 stars. Its [README](https://github.com/ecruells/resident-evil-pc-decomp/blob/15004914527567a2b9cecf34997abe8c252bcbf9/README.md) describes reconstruction from the 1997 PC executable and claims complete functional desktop playability. That is an upstream claim, not locally reproduced. The actual GPL-3.0 notice is outside this intake's permissive route; it also does not clear original Capcom media or all inherited-code provenance.

The reviewed [Linux CMake](https://github.com/ecruells/resident-evil-pc-decomp/blob/15004914527567a2b9cecf34997abe8c252bcbf9/CMakeLists.txt) selects C++17 game/platform units with `-m32`, installed SDL2 and FFmpeg libraries for AVI decoding/resampling. Exact system sonames, build configuration, codecs and transitive grants remain release-specific. This review does not label every possible FFmpeg configuration GPL or certify one as permissive. No library binary was fetched.

The current scheduler is more portable than the Windows assembly alone suggests: `TaskScheduler.cpp` uses MSVC x86 stack switching for Windows and `ucontext` primitives for the alternative branch. Browser adaptation must address that coroutine contract, allocation/guard assumptions, host scheduling, graphics and persistence; the older assembly notes alone are not proof of universal x86 dependence or impossibility. No Emscripten target was established in the selected build files.

The game still needs original region asset trees, model/room/script data, fonts, background art, audio and video. The asset migrator copies/converts those files from purchased installations or disc images; conversion does not create independent replacement content. Reopen with an accepted code route, inherited-code provenance, a complete authored content set, selected dependency audit and tested browser runtime. This is a decompilation-derived port, not emulation or a finished ROM-free addition here.
