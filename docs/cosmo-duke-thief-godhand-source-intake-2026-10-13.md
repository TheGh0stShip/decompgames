# Cosmo, Duke II, Thief 3, God Hand and Prince of Persia intake — October 13

Five game identities, seven repositories, no catalog duplicates. This is a pinned source and documentation audit, not a build or gameplay test. The catalog stays at 84. No retail data, executables, screenshots, SDK packages, dependency library binaries or release bundles were fetched. Selected textual source files, including the legacy startup source exception, were inspected privately; [snapshot hashes](cosmo-duke-thief-godhand-source-snapshots-2026-10-13.json) record the evidence. Mario Party 2/3 and Halo work remains untouched.

## Cosmore and the modern native adapter

`smitelli/cosmore` at `80418d1ee9026594e4dcc8445ec801d374074d84`, 145 stars at read. The [README](https://github.com/smitelli/cosmore/blob/80418d1ee9026594e4dcc8445ec801d374074d84/README.md) describes a reconstruction of v1.20 from the original executable, reporting 96.30% load-image agreement rather than exact whole-file identity. That is an upstream result, not independently reproduced here. It requires original `COSMOx.STN` and `COSMOx.VOL`. Shareware availability does not establish CC0 or permission for an independently branded replacement distribution.

Its [MIT licence](https://github.com/smitelli/cosmore/blob/80418d1ee9026594e4dcc8445ec801d374074d84/LICENSE) and source headers credit the reconstruction authors and the original Apogee game separately. No original rights-holder grant for the reconstructed retail logic was established in this review. The README expressly excludes Borland `src/C0.ASM` and LZEXE/tool documentation from its blanket MIT statement. The documented Turbo C 2.0/TASM 1.0 DOS build therefore cannot be treated as a uniformly MIT source/runtime package. [Modern compiler notes](https://github.com/smitelli/cosmore/blob/80418d1ee9026594e4dcc8445ec801d374074d84/MODERN-COMPILERS.md) alone describe object compilation, with missing host I/O preventing a linked native executable.

`digows/cosmo` at `7844b9126c54f074e643e0d5806c69e1e382d94b`, five stars at read, is a materially more practical native adaptation of that same pinned reconstruction. Its [source preparation](https://github.com/digows/cosmo/blob/7844b9126c54f074e643e0d5806c69e1e382d94b/cmake/PrepareCosmoreSources.cmake) transforms C/headers, fixes integer widths and applies explicit patches. Only generated `game1.c` and `game2.c` enter the reconstructed game source list; `C0.ASM`, LZEXE, original `main.c` and extracted reference drawing routines are not selected there. This avoids those legacy build inputs; it does not clear inherited game code or embedded data.

[CMake](https://github.com/digows/cosmo/blob/7844b9126c54f074e643e0d5806c69e1e382d94b/CMakeLists.txt) uses C11/C++17, SDL3 and ymfm. The actual submodule gitlinks match Cosmore above and ymfm `17decfae857b92ab55fbb30ade2287ace095a381`. ymfm's selected OPL/ADPCM/PCM sources and [BSD-3-Clause notice](https://github.com/aaronsgiles/ymfm/blob/17decfae857b92ab55fbb30ade2287ace095a381/LICENSE) were read separately. SDL's fallback `release-3.4.12` resolves to `f87239e71e42da91ca317a12eefb82cfbf3393eb`; its [zlib-style licence](https://github.com/libsdl-org/SDL/blob/f87239e71e42da91ca317a12eefb82cfbf3393eb/LICENSE.txt) was checked separately. This is selected dependency evidence, not a linked closure audit: a system SDL can differ, and its enabled transitive components plus compiler/browser runtime still need inventory.

The native [platform main](https://github.com/digows/cosmo/blob/7844b9126c54f074e643e0d5806c69e1e382d94b/src/platform/platform_main.c) starts the game on an SDL thread and presents/polls/times hardware on a blocking host loop. A browser adaptation needs a suitable scheduler or worker/thread arrangement, audited memory/interrupt synchronization, browser persistence and a muted host. No current WASM build or gameplay was attempted. The README's desktop playability claims are upstream claims only. Its hardware compatibility includes EGA/timer/audio emulation; that does not make the whole game a DOS CPU emulator or certify clean-room development.

The apparent replacement-content lead is insufficient. [make-episode.py](https://github.com/digows/cosmo/blob/7844b9126c54f074e643e0d5806c69e1e382d94b/tools/make-episode.py) writes one authored map while copying the entire original STN and borrowing bonus maps, title/end/exit screens, demo data, background and music from VOL. It is a mod generator, not an independent asset pack. The adapter's [font loader](https://github.com/digows/cosmo/blob/7844b9126c54f074e643e0d5806c69e1e382d94b/src/platform/font.c) also reads the game's original font. The [game source](https://github.com/smitelli/cosmore/blob/80418d1ee9026594e4dcc8445ec801d374074d84/src/game1.c) contains resource/music lists, sprite-layout contracts and interface strings; these need a separate content inventory before generating replacements.

Reopen only after establishing an acceptable reconstructed-code provenance/grant route, excluding legacy restricted inputs from the exact build, independently authoring all needed graphics/animation/font/text/maps/audio/demo data with a manifest, and verifying the actual native game in a ROM-free muted browser. No generic teaching level would count as the complete original game.

## Duke Nukem II: reconstruction versus rewritten engine

`lethal-guitar/Duke2Reconstructed`, `980cee990879fa5f9e53706ef63ad25df8e32d2d`, 370 stars at read: [README](https://github.com/lethal-guitar/Duke2Reconstructed/blob/980cee990879fa5f9e53706ef63ad25df8e32d2d/README.md) reports original-binary reproduction using legacy Borland/Turbo C++ tooling. [GPL-2.0](https://github.com/lethal-guitar/Duke2Reconstructed/blob/980cee990879fa5f9e53706ef63ad25df8e32d2d/LICENSE.md) blocks the current permissive shortlist regardless of whether replacement art is made. The tree also includes Borland startup assembly and a prebuilt digital-sound object, with source credited to a separate original sound-library author; those components must be independently reviewed before any alternative release. The sound object itself was not fetched. No DOS emulator packaging is being counted as a native browser port.

`lethal-guitar/RigelEngine`, `30afeff8f0b105eac77ee0a2fbd54b06e1a49b60`, 1,007 stars at read: [README](https://github.com/lethal-guitar/RigelEngine/blob/30afeff8f0b105eac77ee0a2fbd54b06e1a49b60/README.md) identifies a modern rewrite using the disassembly as reference, requiring original game data and marking its former WebAssembly demo unavailable. [GPL-2.0](https://github.com/lethal-guitar/RigelEngine/blob/30afeff8f0b105eac77ee0a2fbd54b06e1a49b60/LICENSE.md) is separate from game data. [Selected targets](https://github.com/lethal-guitar/RigelEngine/blob/30afeff8f0b105eac77ee0a2fbd54b06e1a49b60/src/CMakeLists.txt) include SDL2/mixer, DBOPL and Nuked-OPL3 plus an Emscripten branch. Technical port potential exists; no exact dependency closure or working present build was established. Reopen these GPL projects only if the user changes the accepted code-license route, followed by code/content/dependency review and independent gameplay content.

## Thief 3 and God Hand: matching progress is not browser completion

`Veradictus/Thief3-Decomp`, `0022f3be04fa1e0b8900cb575e6113fae3d30120`, six stars at read. The pinned [progress report](https://github.com/Veradictus/Thief3-Decomp/blob/0022f3be04fa1e0b8900cb575e6113fae3d30120/progress/PC_20040610/report.json) reports 576,810 of 5,136,216 code bytes matched (11.230252%) and 7,980 of 23,924 functions matched. These are upstream metrics, not a reproduced result. [Configure](https://github.com/Veradictus/Thief3-Decomp/blob/0022f3be04fa1e0b8900cb575e6113fae3d30120/configure.py) splits original `T3Main.exe` and uses VC++ 2003-era matching settings. The SDK is a Windows `dinput8.dll` loader for the installed retail executable. Its [README licence scope](https://github.com/Veradictus/Thief3-Decomp/blob/0022f3be04fa1e0b8900cb575e6113fae3d30120/README.md) explicitly requires the user's original game and excludes original executable, content and names from the contributors' MIT grant. [Third-party notices](https://github.com/Veradictus/Thief3-Decomp/blob/0022f3be04fa1e0b8900cb575e6113fae3d30120/THIRD_PARTY_NOTICES.md) separately cover MinHook/HDE BSD-2-Clause and bundled CPython; Tauri/crate/npm closure remains unaudited. Reopen when a sufficiently reconstructed portable runtime, accepted inherited-code provenance and a full independent content pack exist; mod-loader startup is not that result.

`LucasPicoli/god-hand-decomp`, `58bcee16a279f8ee2bc2a7e9d341a33b325d4151`, 53 stars at read. The [README](https://github.com/LucasPicoli/god-hand-decomp/blob/58bcee16a279f8ee2bc2a7e9d341a33b325d4151/README.md) distinguishes retail-ELF identity from C reconstruction: undecompiled routines remain original-input-derived assembly, and its stated goal has no port. The [progress report](https://github.com/LucasPicoli/god-hand-decomp/blob/58bcee16a279f8ee2bc2a7e9d341a33b325d4151/progress/report.json) reports matched code 43.530354% and complete code 42.246325%, not 100% reconstructed C. The MIT scope expressly leaves the original game, code and assets with Capcom. The [build script](https://github.com/LucasPicoli/god-hand-decomp/blob/58bcee16a279f8ee2bc2a7e9d341a33b325d4151/compile.py) selects PS2 compiler/assembler paths; proprietary SDK downloads were not performed or cleared. Reopen only with portable reconstructed logic, acceptable original-code provenance, independent complete content and an audited browser toolchain/runtime. A reassembled original ELF running in an emulator would not meet this intake.
