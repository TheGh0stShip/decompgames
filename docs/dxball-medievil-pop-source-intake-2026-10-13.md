## DX-Ball: portable core versus a portable game

`N0zoM1z0/dx-ball`, `d61b0d418cc90229bf956b3275dba6b7670798f8`, 49 stars at read. The [README](https://github.com/N0zoM1z0/dx-ball/blob/d61b0d418cc90229bf956b3275dba6b7670798f8/README.md) documents reconstruction from the English v1.07 executable through Ghidra/REA, refined by original-era compiler and behavior comparisons. This is a documented reconstruction, not independent clean-room evidence. Its [MIT license](https://github.com/N0zoM1z0/dx-ball/blob/d61b0d418cc90229bf956b3275dba6b7670798f8/LICENSE) credits the reconstruction author; an original rights-holder grant covering reconstructed retail logic was not established. The root declaration is not clearance for original resources or recovered runtime code.

The pinned [progress report](https://github.com/N0zoM1z0/dx-ball/blob/d61b0d418cc90229bf956b3275dba6b7670798f8/docs/PROGRESS.md) separately reports 538 provisional candidates, 410 source-present functions, 249 scoped semantic acceptances, 304 byte-exact functions and 68,066 exact code bytes. It identifies 189 runtime dependencies, 43 compiler-generated entries and 36 unclassified origins. These categories overlap and are not a reconstructed-game completion percentage. Reported original-board Windows campaigns under Wine are upstream evidence, not locally reproduced gameplay.

The [build contract](https://github.com/N0zoM1z0/dx-ball/blob/d61b0d418cc90229bf956b3275dba6b7670798f8/docs/BUILD.md) imports an original archive, including executable and data. Windows frontend builds run beside those resources and use DirectDraw/DirectSound/WinMM. The portable route produces a core library and resource/board inspectors. A Windows build without embedded resources is a compilation option, not evidence of ROM-free gameplay. No source archive, original resource object or prebuilt game was imported here.

[CMake](https://github.com/N0zoM1z0/dx-ball/blob/d61b0d418cc90229bf956b3275dba6b7670798f8/CMakeLists.txt) selects a shared C11/C++11 core, Unix `libm`/host helpers, Windows service imports and a Windows-only game executable. Its rebound code explicitly relies on GNU x87 excess-precision behavior; that needs a deliberate browser behavior check rather than assuming a wasm32 compile preserves it. A browser frontend, scheduler, graphics/file/audio/persistence adapters and exact SDK/runtime closure are unverified.

Selected [CRT provenance](https://github.com/N0zoM1z0/dx-ball/blob/d61b0d418cc90229bf956b3275dba6b7670798f8/config/crt-provenance.json) distinguishes original compiler/runtime families. It is an origin inventory, not a grant or proof that each recovered routine is shipped. A release would need the exact selected source/runtime boundary and its notices, separately from matching-only proprietary toolchains. The private resource inventory likewise records original MDS/WAV/PCX/SBK and other content identities without licensing them. Reopen after acceptable inherited-code provenance/grants, a complete independently authored graphics/animation/font/text/board/audio/resource pack and an audited native browser adaptation. The game's small genre alone does not remove those gates.

[Main split configuration](https://github.com/MediEvilDecompilation/medievil-decomp/blob/6afe6fe35d5ddf0ce1bebdb2e72f8215b5b5b407/config/splat.main.yaml) requires `disk/SCUS_942.27`; the game configuration requires `disk/MEDIEVIL.EXE`. Splat, m2c, asm-differ and maspsx gitlinks are recorded as build/reconstruction tools, not certified runtime components. PSX/PsyQ interface provenance, the exact selected tool/runtime grants and original content require separate review. No compiler binary, assembly extraction, PS1 image or assets were fetched. There is no established native/browser gameplay target or independent model/animation/world/audio/text pack.

`alexbeavs-ps1-ports/medievil-recomp`, `f8eb216f10ef7f644b33643330b967cd29562709`, seven stars, is another implementation of the same title. Its [README](https://github.com/alexbeavs-ps1-ports/medievil-recomp/blob/f8eb216f10ef7f644b33643330b967cd29562709/README.md) describes static recompilation with a PSX runtime, requiring original disc data and a retail SCPH-1001 BIOS. The project-owned code is GPL-3.0-only; its [third-party notice](https://github.com/alexbeavs-ps1-ports/medievil-recomp/blob/f8eb216f10ef7f644b33643330b967cd29562709/THIRD_PARTY_NOTICES.md) excludes generated retail code and game content. Exact `RetroPortingToolKit/recomp-ui` gitlink `be8ac1d03ee19d55394b5a5f2d9d1506edd56659` is MIT. The launcher grant does not supersede either the noncommercial runtime or the generated game/BIOS requirements. No dependency code or closure was fetched or built.

The pinned [validation receipt](https://github.com/alexbeavs-ps1-ports/medievil-recomp/blob/f8eb216f10ef7f644b33643330b967cd29562709/docs/VALIDATION.md) says unpublished and records a 25-second hidden run with a self-resolving watchdog snapshot; visible gameplay and exact-package tests remain required upstream. This was not our test and is not a completed playthrough. Reopen the reconstruction only with suitable code grants/provenance, portable reconstructed gameplay and independent content; the recomp additionally needs an acceptable runtime license and a route excluding retail-generated code/data/BIOS. Neither current bundle is eligible for this ROM-free permissive intake.

No standard permissive game-distribution grant was established. This must not be relabeled MIT or treated as an original-asset permission route for the already researched GPL SDLPoP implementation.

Only the two textual grant/readme files and tree metadata were downloaded. No assembly, disk routines, copy-protection code, support payloads or executable/asset files were fetched. Running a rebuilt Apple II program in an emulator would not create a native decompilation port. Reopen only when a suitable distribution grant and independent-content/native-browser route are documented; preserve the source-archive classification.
