## Melee: browser potential does not resolve the code grant

`HexDump0/melee`, `33d262eabfb9b610026841784a2dad1721f7c056`, five stars at read, is a native port called Melee Unbound. Its exact `decomp` gitlink is `doldecomp/melee` at `40012f51f0f1ddeff397a7f5f267bfa5441236d8` (2,402 stars at read). The upstream [guide](https://github.com/doldecomp/melee/blob/40012f51f0f1ddeff397a7f5f267bfa5441236d8/docs/getting_started.md) aims at C matching PowerPC assembly, and its [README](https://github.com/doldecomp/melee/blob/40012f51f0f1ddeff397a7f5f267bfa5441236d8/.github/README.md) calls it WIP and builds `GALE01` version 1.02 `main.dol` from original disc-extracted input. Matching/rebuild results were not reproduced here. Licenses found under upstream tooling do not establish a grant for the reconstructed game source.

The port's [THIRD-PARTY.md](https://github.com/HexDump0/melee/blob/33d262eabfb9b610026841784a2dad1721f7c056/THIRD-PARTY.md) expressly limits MIT to its own native/platform, launcher, mods, site, patches and tooling. It excludes the decompilation and Nintendo's game, and notes the upstream has no license file for that code. This is a definite scope limitation, not a missing badge to work around. Its controller diagram is separately CC BY 3.0 with modification/attribution requirements; it is not CC0 and would not clear game models, animations, stages, voices or menus.

There is concrete browser build work. [wasm_census.sh](https://github.com/HexDump0/melee/blob/33d262eabfb9b610026841784a2dad1721f7c056/native/tools/wasm_census.sh) compiles reconstructed game C and port units using Emscripten's SDL3 port, WebGL2, function-pointer-cast adaptation and default JSPI suspension, with an Asyncify option. [build-play.sh](https://github.com/HexDump0/melee/blob/33d262eabfb9b610026841784a2dad1721f7c056/site/scripts/build-play.sh) adds a separate `wasm-opt` pass and stages JS/WASM. These scripts were read, not executed. Build success, browser compatibility/performance and game completion are unverified here; no upstream player was opened.

Dependency scope matters: WAMR gitlink `25bd7eb63e828e4bd242cc9b38d260b4b31c6605` has an [Apache-2.0 notice with LLVM exceptions](https://github.com/bytecodealliance/wasm-micro-runtime/blob/25bd7eb63e828e4bd242cc9b38d260b4b31c6605/LICENSE), separately read. A guessed `NOTICE` path returned 404; that is not a whole-tree notice search. The [desktop mod target](https://github.com/HexDump0/melee/blob/33d262eabfb9b610026841784a2dad1721f7c056/native/mod/wamr/CMakeLists.txt) selects interpreter-only WAMR. The browser census instead compiles the default mod directly and explicitly omits WAMR. It must not be counted as a linked browser dependency merely because it is vendored. SDL3's resolved port, SDK headers/libraries/emitted JS, Khronos headers and other selected components still need an exact closure if the code gate is ever resolved.

The port requires the visitor's Melee disc data for data-loading builds/runs. GX/AX hardware compatibility does not mean the whole game is CPU emulation; conversely, native decompiled logic does not establish independently authored assets or clean-room development. Reopen only with acceptable whole-game code provenance/grants, a fully independent graphics/model/animation/audio/text/stage/data pack and a scoped ROM-free muted browser acceptance result.

## Budokai Tenkaichi 3: contributor CC0 excludes the reproduced program

`z3xox/BT3-Decompiled`, `95b950367364137130758ef82a218e607a54b703`, 21 stars, is separately pinned from its default branch. `z3xox/Tenkaichi3Decomp`, `2080bfeb9604a04c9270d849df08a05eafcf2d5b`, 278 stars, is the native PC port. They are one game; this review did not prove which upstream commit was incorporated into the port's copied source tree.

The upstream [README](https://github.com/z3xox/BT3-Decompiled/blob/95b950367364137130758ef82a218e607a54b703/README.md) reports 99.92% matching game code for `SLUS_216.78`, 99.97% for menu `DBZP.BIN`, byte-identical rebuilt binaries, four remaining originally authored VU0 assembly routines and nine VU1 listings. Those are upstream claims, not reproduced metrics. Its percentages exclude Sony SDK and CRI sound libraries. The documented matching build extracts/splits original binaries and requires separate PS2 compiler/binutils; none were fetched.

Its CC0 dedication covers the authors' names, comments, documentation, scripts/build configuration and reconstruction work, while expressly excluding the reproduced game. The port's [license scope](https://github.com/z3xox/Tenkaichi3Decomp/blob/2080bfeb9604a04c9270d849df08a05eafcf2d5b/README.md) likewise limits MIT to its own port/setup/tools and `PORT` changes, excluding inherited `src/` and `include/` game code. Neither declaration establishes a permissive grant for the intended whole reconstructed game distribution.

The PC port can build release executables without a disc using shape-only built-in tables, but it obtains their values from the original disc when running. A disc-free compile is therefore not ROM-free gameplay. Original fighters, animation/event data, effects, stages, menus, movies and sound still need a complete independent inventory and replacement pack.

Custom-content support is promising but insufficient: [added-stage documentation](https://github.com/z3xox/Tenkaichi3Decomp/blob/2080bfeb9604a04c9270d849df08a05eafcf2d5b/docs/port/adding_stages.md) retains a base disc sound bank for additional `.unk` maps. [Added-song documentation](https://github.com/z3xox/Tenkaichi3Decomp/blob/2080bfeb9604a04c9270d849df08a05eafcf2d5b/docs/port/adding_songs.md) describes creating menu lettering from original stage/song-name pictures. Mods, manifest support and new music do not replace the remaining disc content. No sample custom map/song or derived lettering was fetched.

Selected notices were checked independently: ImGui/MIT, xxHash/BSD-2-Clause, dr_libs' alternative Unlicense/MIT terms and Bitstream Vera/DejaVu font terms (DejaVu changes public domain; the whole font is not CC0). `COPYING.NEWLIB` is a multi-origin notice with per-file terms and additional referenced conditions, not a uniform BSD grant. Its exact selected math functions and full closure remain unaudited. The documented PC renderer is Vulkan or OpenGL 3.3 with desktop setup/release scripts; no verified browser adaptation was established. Reopen after a suitable game-code grant/provenance route, independent tables/content and an audited browser runtime, rather than importing the desktop bundle.

## Fatal Frame II: two separate implementations, one identity

`Mikompilation/Mikompilation`, `afd5bc1692cd9a11e39416abb66b23a0082ccd69`, 57 stars, declares [BSD-2-Clause](https://github.com/Mikompilation/Mikompilation/blob/afd5bc1692cd9a11e39416abb66b23a0082ccd69/LICENSE) for the reconstruction author's work. A grant/provenance route covering inherited retail code was not established. The README sets a playable PC port as its goal; it does not substantiate completed gameplay. The selected [main](https://github.com/Mikompilation/Mikompilation/blob/afd5bc1692cd9a11e39416abb66b23a0082ccd69/zero_rom/zero2np/src/main/main.cpp) runs an unconditional phase loop, with much graphics/DMA/memory-card/game initialization commented out and an explicit not-implemented diagnostic. This supports an early reconstruction/reimplementation classification, not a complete native game or a reproduced matching binary.

Its [build instructions](https://github.com/Mikompilation/Mikompilation/blob/afd5bc1692cd9a11e39416abb66b23a0082ccd69/docs/Build.md) are a placeholder, and its asset directory asks for game assets. CMake selects C++17 source units and spdlog. In the [third-party target file](https://github.com/Mikompilation/Mikompilation/blob/afd5bc1692cd9a11e39416abb66b23a0082ccd69/third-party/CMakeLists.txt), SDL2 and ImGui additions are commented out. Their separately read zlib/MIT notices therefore do not establish selected runtime components or clear spdlog/bundled fmt. No full implementation, independent content or browser scheduler/render/file/persistence route was established.

`Mikompilation/MioPan`, `08c76476f90a3024da2c1c57981e0bcf9ed00300`, six stars, is a separate [prototype-derived source reconstruction/native port](https://github.com/Mikompilation/MioPan/blob/08c76476f90a3024da2c1c57981e0bcf9ed00300/README.md), using February 6, 2004 prototype debug symbols/line tables/link map and SDL3 platform shims. It reports early crashes/missing effects/render differences; no completeness or matching claim was reproduced here. It is AGPL-3.0, outside the current accepted permissive route, and requires original `IMG_BD.BIN`. It is not the earlier BSD implementation relabeled, and neither a second game nor a clean-room certification.

Its selected CMake route uses a native host compiler, SDL3, shadercross, spdlog, cglm, ImGui and ImPlot. SDL3 fetches `release-3.4.12`; no fetched dependency code or resolved closure was inspected. Optional FFmpeg searches a prebuilt tree; the inspected vendored `extern/ffmpeg/LICENSE` is GPL-3.0 text, separate from MioPan's AGPL. No binary was fetched, no exact FFmpeg configuration was established, and optional omission would not resolve MioPan's own terms or original content. Reopen only if the accepted code route changes or suitable alternative grants exist, with independent data and a verified browser implementation; the early BSD project would additionally need complete portable reconstructed gameplay.
