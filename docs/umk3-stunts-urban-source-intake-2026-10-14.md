## UMK3: a Web harness is different from the full native target

The [selected license](https://github.com/MaryNCRT/Ultimate-Mortal-Kombat-3-iOS-Recomp/blob/8b16441efdc47f9b1eea6ce3a036552a8e827cb2/LICENSE) limits MIT to contributors' tools, runtime, handwritten C and documentation, expressly withholding a grant for the original game. No separate original rights-holder grant was established here. The [methodology](https://github.com/MaryNCRT/Ultimate-Mortal-Kombat-3-iOS-Recomp/blob/8b16441efdc47f9b1eea6ce3a036552a8e827cb2/docs/METHODOLOGY.md) describes reconstruction and differential comparison with a static ARM-to-C oracle. Its claims about 2,572 functions and native alpha playability were not independently reproduced; they are not byte-matching or clean-room certification.

The [Web instructions](https://github.com/MaryNCRT/Ultimate-Mortal-Kombat-3-iOS-Recomp/blob/8b16441efdc47f9b1eea6ce3a036552a8e827cb2/web/README.md) require a locally supplied IPA or extracted resources. More decisively, [CMake](https://github.com/MaryNCRT/Ultimate-Mortal-Kombat-3-iOS-Recomp/blob/8b16441efdc47f9b1eea6ce3a036552a8e827cb2/CMakeLists.txt) connects the Emscripten entry to `umk3-test`, which selects `fight_scene.c` and `fight_stubs.c`. That scene identifies its own invented state-machine/timing behavior. The separate full `umk3-game` target includes the larger logic set and requires an original executable to generate fight tables, arena names and playback scripts. An existing wasm32 pointer-size allowance is not proof that the full target has a completed browser platform adapter.

Selected Web code uses SDL2 and SDL2_mixer with MP3 support; exact decoder/SDK/runtime grants and emitted closure remain unaudited. No complete independent resource/table pack is established. Gates: inherited-code permission, independent full content and tables, actual full-game Web selection, dependency notices, then ROM-free gameplay/save/Stop verification. No IPA or extracted game resources were acquired.
