# Prism Foundry integration groundwork

Authored MIT animation/descriptor adapters and course-selection code for the Moon Child FE source-port experiment. A later private player passes a muted three-course playthrough with all nine pickups, three gates and final victory, plus separate startup/control/retry/fall/Stop checks. Authored save/resume now preserves earned pickups and checkpoint progress across a full browser restart. **No new catalog entry or production release.** Final source/dependency/distribution gates remain open. Interfaces and retained callers were inspected; this is not a clean-room certificate.

`animation.cpp` replaces `Classes/moonchild/anim.cpp`. It bounds forced frames against the actual frame count, handles null/empty sequences, rejects invalid sequence indices, and preserves ordinary forward/reverse stepping. `assets.cpp` replaces `Classes/moonchild/asset.cpp`: descriptor-validation failures leave the target lists empty, before newly parsed assets are committed. It retains actual native sprite construction and PCX decoding after checking the selected image profile.

This profile requires single-plane 8-bit RLE, zero origin, even width with no padded scanline, dimensions at most 2048×4096, a complete palette and no trailing bytes. Frame paths are limited to 80 characters because the retained `Cblitbuf` constructor uses a 100-byte diagnostic buffer. Descriptors are capped at 256 KiB, lines at 250 characters, frames per sequence at 100, concrete sequence slots at 21, total frames at 4096, sequence/animation definitions at 256 each and decoded sprite pixels at 16 MiB. This is a controlled authored-content profile, not a general PCX compatibility or arbitrary-input safety certificate.

`make-levels.py` generates CC0 course constants from the existing authored `campaign.json`. `FoundryConfigureLevels()` selects the three corresponding native `LEVEL_DESCR` entries and empties the other 17 runtime entries. The original boundary harness only checks descriptor selection; the later private player executes all three course initializers and the authored callbacks. All three checkpoint positions activate, each gate advances normally, and final victory is earned. An activated first-course checkpoint also passes fall/respawn verification after a saved-game browser restart. Original source-side tables and unused campaign routines have not all been purged or reviewed merely because the runtime descriptor selector exists.

Tests accept the 21-slot/100-frame boundaries and four 4-MiB sprites at the aggregate limit; reject a fifth such sprite, 22 slots, 101 frames, malformed/missing content and other invalid cases; and compare all 265 actual native-decoded image/palette SHA-256 values during full content replay. See the [measured checkpoint](../../docs/prism-foundry-bounds-levels-2026-10-15.md). The old source-only and content-only receipts remain separate historical results. No runtime or complete source archive is published here.

## Private player recipe

```text
python build-player.py --base-build ADAPTED_88_UNIT_BUILD --pack AUTHORED_PACK --output NEW_OUTPUT_DIRECTORY --emscripten EMSCRIPTEN_DIRECTORY --em-config EMSCRIPTEN_CONFIG
node test-player.mjs PRIVATE_PLAYER_DIRECTORY
node test-player.mjs PRIVATE_PLAYER_DIRECTORY --route
```

The current player recipe verifies the pinned source/overlays, exact pack allowlist and **82 retained native objects**. Eight changed/new units provide patched MC/Host/main, the two bounded adapters, authored level/progress selection and a pickup-recording hook in the native diamond unit. The older six-unit/83-object player receipt remains historical. The recipe bypasses original movie/menu/progress flows, disables editor access, selects null audio and omits original palette/world presentation updates. It maps pickup bursts to authored content, uses fixed normal controls, and adds a campaign fall/respawn path through native `hoi_init`; the original collapse/rise animation is not exercised. Normal native actor movement, collision and pickup callbacks remain. Read-only state exports support test evidence; they do not move actors, grant pickups or advance courses. Save data is consumed by a distinct production initialization path, not by test-only mutation exports.

The later candidate uses `--strip-campaign-tables`: **79 retained objects plus ten changed/new units**. It generates globals with an empty 20-slot level matrix, removes 14 original trigger lists and 14 map descriptors, replaces the 16-row scroll-trigger schedule with a terminal sentinel, and omits both original `levinits.cpp` and `trigger.cpp` objects. Authored object callbacks handle this campaign's progression. Unexpected native exit flags retry the authored course, and shutdown only frees selected campaign resources. This removes original placement roots; remaining source-side expressive data and unused UI/special-case routines still need review. Pinned upstream inputs and earlier boundary-test sources are preserved.

The wrapper supplies New game/Resume/Stop and automatically saves meaningful authored progress. Stop asks the Host to end its loop and destroy native resources; the test observes `Ready` becoming false before removing the iframe. The test launches headless Edge with `--mute-audio`, uses ordinary keyboard input and closes the browser/server in `finally`. The `--route` check remains partial: two pickups and one gap fall in Assembly Floor, with both pickups retained after respawn. It is not a three-course playthrough.

The [private-player checkpoint](../../docs/prism-foundry-player-2026-10-15.md) records a removed original-water-animation crash and the remaining WebGL warning, dependency, source-content and release gates. A [later progression check](../../docs/prism-foundry-progression-2026-10-15.md) tests the readiness guard, cancellation during loading and earned three-course completion. Assertions/SAFE_HEAP at final link do not establish complete memory safety. No runtime is placed in the public game catalog by these recipes.

`test-player.mjs PRIVATE_PLAYER_DIRECTORY --loading-stop` delays the first WASM request, observes the pre-initialization state return `null`, cancels that player without calling native exports, then performs normal startup/control/retry and two native shutdown checks. `test-campaign.mjs PRIVATE_PLAYER_DIRECTORY` attempts all courses using ordinary keyboard input and read-only observations. The report distinguishes completed courses from an unsuccessful full attempt; `--first-only` limits it to the first gate. Both wrappers are guarded by actual runtime initialization, not merely the existence of Emscripten export stubs. Cancellation during loading is labeled as context removal, never native shutdown.

## Authored save/resume

`save.js` validates a small versioned record bound to the authored pack's SHA-256 revision. Only course, three-bit prism identity mask, checkpoint activation and final completion are stored in the dedicated `decompgames.prism-foundry.progress.v1` localStorage key. It stores no arbitrary position, original game save file or original campaign content. New game starts a fresh campaign; Resume selects a validated save. Unavailable storage is reported in the wrapper.

`FoundryProgress.cpp/.h` initialize native progress, select only the authored spawn/checkpoint, omit already collected prism actors and restore the corresponding native pickup counter. The generated level overlay and a native diamond collision hook record pickup identity before the flying HUD effect finishes. R resets the current course. The earlier `FoundryLevels.cpp`/boundary-test source is preserved; the player recipe generates its save-aware derivative in the private build directory.

`node test-save-codec.mjs` checks 49 valid record combinations, 23 rejected records, three invalid live snapshots and one live-snapshot conversion. `node test-campaign.mjs PRIVATE_PLAYER_DIRECTORY --save-restart` uses a fresh persistent Edge profile, earns two prisms and a checkpoint, closes the full browser, resumes the earned save, deliberately falls and verifies checkpoint respawn while retaining both pickups, then continues the campaign. The test reads its save key; it does not seed or edit storage or native state. See the [save checkpoint](../../docs/prism-foundry-save-2026-10-15.md) for measured terminal-save restoration and release limits.

## Runtime input audit

`python audit-runtime.py --build PRIVATE_PLAYER_DIRECTORY --output NEW_AUDIT_DIRECTORY --em-config EMSCRIPTEN_CONFIG` verifies the candidate outputs and relinks with `--trace` and a linker map. It records persistent object/archive file hashes, selected archive-member names and any transient inputs missing after link cleanup. The audit output name changes the WASM debug module-name subsection from `foundry.wasm` to `audit.wasm`; the recipe compares every other section/subsection byte. It does not execute either module or certify full dependency licensing.

The [campaign-root/runtime checkpoint](../../docs/prism-foundry-roots-runtime-2026-10-15.md) records the latest muted gameplay/save replay, ten selected SDK archives and [eight copied primary notice documents](notices/README.md). Complete SDK per-file/source/distribution closure remains open.

`python audit-sdk-sources.py --sdk EMSCRIPTEN_DIRECTORY --output NEW_SOURCE_AUDIT_DIRECTORY --verify-primary` maps those 380 traced archive members to distinct component translation units, preserves local source bytes and compares primary versions. `python collect-sdk-notices.py --audit SOURCE_AUDIT_DIRECTORY --sdk EMSCRIPTEN_DIRECTORY --output NEW_NOTICE_AUDIT_DIRECTORY` inventories notice-bearing source comments, verifies both SDK recipes and preserves SDL's separate YUV license. See the [SDK-source follow-up](../../docs/prism-foundry-sdk-sources-2026-10-15.md) for measured results. These scripts do not rebuild SDK archives, capture transitive headers or certify complete dependency clearance.
